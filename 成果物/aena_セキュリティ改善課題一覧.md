# aena セキュリティ改善課題一覧（現状課題 → 改善後プラクティス）

- 作成日: 2026-07-27
- 対象: aena インフラ/システムのセキュリティ改善
- 目的: 過去の考察・課題抽出を踏まえ、改善が必要な要素をリスト化し、右列に「改善後のあるべきプラクティス」を対比整理する。
- 備考: 本リポジトリ内には過去の aena 固有の課題抽出データが残っていなかったため、一般的なセキュリティベストプラクティス（NIST / CIS Controls / ゼロトラスト等）をベースに整理した雛形。aena 固有の事情に合わせて各行を追記・修正して運用する。

## 1. 認証（Authentication）

| # | 改善が必要な要素（現状課題） | 改善後のプラクティス |
| --- | --- | --- |
| 1-1 | ID/パスワードのみの単要素認証 | 全アカウントで **MFA（多要素認証）を必須化**。管理者・特権アカウントはハードウェアトークン/FIDO2 を優先 |
| 1-2 | パスワードポリシーが弱い／使い回し | 長さ重視（12文字以上）＋パスワードマネージャ配布。既知漏洩パスワードのブロック、定期強制変更は廃止 |
| 1-3 | サービスごとに個別認証（ID分散） | **SSO / IdP 統合（SAML・OIDC）** に集約し、認証を一元管理・一括失効を可能に |
| 1-4 | 退職・異動時のアカウント削除が手動/遅延 | IdP と人事システム連携で **入退社に応じた自動プロビジョニング/デプロビジョニング** |
| 1-5 | 共有アカウントの利用 | 共有アカウントを廃止し **個人単位のアカウント**へ。やむを得ない場合は Vault 経由で払い出し・監査 |

## 2. 認可・アクセス管理（Authorization / IAM）

| # | 改善が必要な要素（現状課題） | 改善後のプラクティス |
| --- | --- | --- |
| 2-1 | 権限が過剰（付けっぱなし） | **最小権限の原則**。ロールベース（RBAC）/属性ベース（ABAC）で必要最小限に |
| 2-2 | 特権アカウントの常時保持 | **Just-In-Time（JIT）権限昇格** ＋ 特権アクセス管理（PAM/Vault）で一時払い出し・自動失効 |
| 2-3 | 権限棚卸しが未実施 | 四半期ごとの **アクセスレビュー（棚卸し）** を定例化し証跡を保存 |
| 2-4 | 管理者権限の広範な共有 | 管理操作は **踏み台/PAM 経由に限定**し、セッション録画と承認フローを付与 |

## 3. VPN / リモートアクセス

| # | 改善が必要な要素（現状課題） | 改善後のプラクティス |
| --- | --- | --- |
| 3-1 | VPN接続後は社内網へフルアクセス | **ゼロトラスト（ZTNA）へ移行**。アプリ単位のアクセス制御で横展開を遮断 |
| 3-2 | VPNアカウントがMFA未対応 | VPN 認証に **MFA + デバイス証明書** を必須化 |
| 3-3 | 接続元デバイスの健全性を確認しない | 接続時に **デバイスポスチャチェック**（OS更新・EDR稼働・暗号化）を実施 |
| 3-4 | VPN機器のファーム/脆弱性管理が後手 | VPNゲートウェイの **緊急パッチSLA** を定義し、CVE公開時は即時対応 |
| 3-5 | スプリットトンネルで通信が可視化されない | 業務通信は集約しログ取得、または SASE/SSE でクラウド経由に統合 |

## 4. ファイアウォール / ネットワーク

| # | 改善が必要な要素（現状課題） | 改善後のプラクティス |
| --- | --- | --- |
| 4-1 | 「Any-Any」など緩いルールが残存 | **デフォルト拒否（暗黙のdeny）** ＋ 必要通信のみ明示許可 |
| 4-2 | ルールの棚卸し・棚卸履歴がない | 半期ごとのルールレビューで **未使用ルール/シャドウルールを削除** |
| 4-3 | フラットネットワーク（水平移動が容易） | **マイクロセグメンテーション**で本番/開発/管理を分離 |
| 4-4 | 東西通信（内部間）が無監視 | 内部トラフィックも **IDS/IPS・フローログ**で可視化 |
| 4-5 | 変更管理なしでルール追加 | FW変更は **チケット＋承認＋自動化（IaC）** で証跡化 |

## 5. エンドポイント / デバイス

| # | 改善が必要な要素（現状課題） | 改善後のプラクティス |
| --- | --- | --- |
| 5-1 | アンチウイルスのみで検知が弱い | **EDR/XDR** を全端末に導入し、振る舞い検知と自動隔離 |
| 5-2 | ディスク暗号化が任意 | 全端末で **フルディスク暗号化（BitLocker/FileVault）を強制** |
| 5-3 | 私物端末（BYOD）の管理外利用 | **MDM/MAM** で管理下に置き、非準拠端末はアクセス拒否 |

## 6. 暗号化 / 通信保護

| # | 改善が必要な要素（現状課題） | 改善後のプラクティス |
| --- | --- | --- |
| 6-1 | 一部通信が平文/旧TLS | 全通信を **TLS1.2以上（推奨1.3）** に統一、弱い暗号スイート無効化 |
| 6-2 | 保存データが未暗号化 | 機密データは **保存時暗号化（at-rest）** ＋ 鍵管理サービス（KMS）で鍵分離 |
| 6-3 | 証明書の期限切れ/手動管理 | 証明書の **自動発行・更新（ACME）と期限監視** |

## 7. ログ・監視 / 検知

| # | 改善が必要な要素（現状課題） | 改善後のプラクティス |
| --- | --- | --- |
| 7-1 | ログが各機器に分散・短期保存 | **SIEM に集約**し保管期間（例: 1年以上）とタイムスタンプ同期を定義 |
| 7-2 | 不審挙動のアラートがない | 相関ルール/UEBA で **異常検知アラート**を設定 |
| 7-3 | 監視が平日日中のみ | **24/365 監視（SOC/MDR）** 体制、またはオンコール整備 |

## 8. 脆弱性 / パッチ管理

| # | 改善が必要な要素（現状課題） | 改善後のプラクティス |
| --- | --- | --- |
| 8-1 | パッチ適用が場当たり的 | 重大度別の **パッチ適用SLA**（Critical: 短期）を定義し定例運用 |
| 8-2 | 脆弱性スキャンが未実施/散発的 | 定期的な **脆弱性スキャン＋資産インベントリ** と対応トラッキング |
| 8-3 | EOL製品の継続利用 | EOL管理台帳を作り **計画的更改** |

## 9. クラウド設定 / IaC

| # | 改善が必要な要素（現状課題） | 改善後のプラクティス |
| --- | --- | --- |
| 9-1 | 設定ミス（公開バケット等） | **CSPM** で常時構成監査、公開リソースを自動検知・是正 |
| 9-2 | 手作業での構成変更 | **IaC（Terraform等）＋レビュー**で構成をコード化・再現性確保 |
| 9-3 | シークレットのハードコード | **シークレットマネージャ**へ集約し、コードスキャンで漏洩検知 |

## 10. インシデント対応 / 事業継続

| # | 改善が必要な要素（現状課題） | 改善後のプラクティス |
| --- | --- | --- |
| 10-1 | インシデント対応手順が未整備 | **IRP（対応計画）＋連絡体制** を文書化し、定期訓練を実施 |
| 10-2 | バックアップが単一/未検証 | **3-2-1バックアップ＋オフライン/イミュータブル**保管、復元テスト定期実施 |
| 10-3 | 責任範囲が曖昧 | RACI で **役割分担**を明確化、外部連絡（当局/顧客）手順も整備 |

## 優先度サマリ（クイックウィン）

| 優先度 | 施策 | 対応領域 |
| --- | --- | --- |
| 高 | 全アカウントMFA必須化 / VPNのMFA・デバイス証明書 | 認証・VPN |
| 高 | ファイアウォールのデフォルト拒否化・Any-Anyルール撤廃 | Firewall |
| 高 | 特権アクセスのJIT/PAM化と共有アカウント廃止 | 認可 |
| 中 | ゼロトラスト（ZTNA/SASE）への段階移行 | VPN・NW |
| 中 | SIEM集約と検知アラート整備 | 監視 |
| 中 | EDR全台展開・フルディスク暗号化強制 | エンドポイント |
