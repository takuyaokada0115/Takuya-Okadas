# サロン給与計算（月次・総支給）

Mana Lea株式会社 / SSIN STUDIO（下北沢店・町田店）の月次給与を計算する。
**計算範囲は総支給まで**。控除（社保・源泉・住民税）は freee人事労務 が自動計算するため触らない。
対象月 M の勤務分は、翌月(M+1)の20日に支給（freeeの year/month は支給月＝M+1）。

## 必要データ（毎月ユーザーから受領）
1. HPB **スタッフ別集計**（両店）: 各スタッフの総売上/施術/店販/オプ/指名売上/指名数。
2. HPB **店販月別集計**（両店・スタッフ別）: 指名料/美容液/HBL beauty/回数券/キャンペーンの内訳。店舗合計と一致するか検算必須。
3. HPB **売上報告**（両店）: 区分別店販の店舗合計（検算用）。
4. **LINEタイムカード**（全員統合グループのテキスト）: 当月の出勤/退社。
5. freee前月明細（APIで取得）: 固定項目(基本給/みなし残業代/皆勤手当)と前月通勤費。

## 計算ルール
### 売上連動（freee変動手当）
- **売上インセンティブ** = 両店合算の総売上をルックアップ表で引く（段階ではなく表の値をそのまま）:
  650,000→6,500 / 700,000→14,000 / 750,000→22,500 / 800,000→32,000 / 850,000→42,500 /
  900,000→54,000 / 950,000→76,000 / 1,000,000→90,000 / 1,100,000以上→売上×10% / 650,000未満→0。
  （該当総売上以下で最大の行。横井等 両店勤務者は両店合算の総売上で判定）
- **指名料** = 店販内「指名料」カテゴリの合計（両店合算）× 100%。
- **商品OP販売コミッション** = (美容液[物販]＋オプション) × 5%（四捨五入 = floor(x+0.5)）。
  物販には美容液・HBL beauty等の物販商品を含める。回数券・キャンペーン・指名料は対象外。
- 店長手当 20,000（谷本のみ）／町田業務支援手当 10,000（谷本のみ）。

### 勤怠（LINEタイムカード）
- 実労働 = (退社−出勤) − 休憩60分。残業 = 実労働 − 所定8h（下回りは0）。日跨ぎは退社+24h補正。
- 打刻忘れのチャット申告（「◯時出勤しています」「◯時に退社」等）を採用。同日複数打刻は最早出勤/最遅退社。
- **町田ルール**: 谷本・斉藤は出勤打刻が10:50以降の日＝町田勤務とみなし、その日は11:00-20:00（実働8h・残業0）固定。該当日数＝その人の当月町田勤務日数。
- みなし残業枠（正社員/有期・無期 25h、新規有期契約=20h）内なら**追加残業ゼロ**（みなし残業代は契約額据置＝freee固定）。枠超過分のみ別途。
- 再現コード例: `成果物/給与計算エンジン/timecard_parse_202610.py`。

### 手当
- **皆勤手当**（従来どおり・freee固定値を使用）: 谷本5,000 / 他は6,900（有期契約）。
- **土日祝手当**（有期対象者・当月の全土日祝出勤が条件で5,000）。1日でも土日祝を欠くと0。
  祝日判定を忘れない（例: 10月はスポーツの日=第2月曜）。
- **通勤交通費**（原則「前月を参照」。定期は前月額、町田往復分=往復運賃×当月町田勤務日数を加算）:
  - 谷本 = 国領-下北沢定期(9,566) + 下北沢-町田往復(720) × 町田勤務日数。
  - 山口 = 前月と同じ定期額。伊東 = 0。
  - 横井 = 登戸-下北沢定期3ヶ月/3 + 登戸-町田往復 × 町田勤務日数（主たる店舗で定期側が変わる）。
  - 斉藤 = 前月定期額。渡邉 = 祖師ヶ谷大蔵-下北沢定期3ヶ月/3。
  - 定期額が不明な項目はユーザーに確認する。

### 固定項目は freee を正とする
基本給・みなし残業代・皆勤手当は freee人事労務の既存値（前月明細/マスタ）を使用し、上書きしない。
新規有期は研修期間(入社〜約3週)は研修給(212,500円/月)、以降は有期本採用(基本給213,000/みなし12,400/土日5,000/皆勤6,900)。月途中の切替は日割（freeeが計算）。

## freee連携（重要な制約）
- freee人事労務APIで**書込可能なのは固定手当(allowance_rules=皆勤等)・勤怠(work_record_summaries)・備考のみ**。
- **変動手当（売上インセ/指名料/商品OPコミ/店長/町田支援/土日祝/通勤）はAPIで書込不可** → 画面手入力が前提。
  本スキルは「freee入力用」の項目別テーブルを出力し、ユーザーがfreeeの変動手当欄へ入力する。
- 取得API: 従業員一覧 `GET /api/v1/employees`、給与明細 `GET /api/v1/salaries/employee_payroll_statements/{employee_id}?year=&month=`（service=hr, company_id=11975765）。
- freeeの year/month は**支給月**（＝勤務月+1）。例: 10月勤務分は「11月(11/20支払い)」タブ、賃金計算期間は10/1〜10/31。
- 手当マスタ(`GET /api/v1/allowances`)に存在する手当は3つのみ（皆勤手当525500・土日祝手当566849・商品販売コミッション628443＝店販+オプの5%）。売上インセンティブ/指名料/店長手当/町田業務支援手当/通勤交通費は手当ではなく明細直接入力項目でAPI書込不可。

### freeeへの入力は「Claude in Chrome」で行う（確立済みの運用・2026-11）
- クラウドセッションはユーザーのログイン済みfreee画面を操作できない。入力はユーザーPCのChrome拡張「Claude in Chrome」で実施する（クーポン順タスクのサロンボード操作と同じ）。
- 手順: ①ユーザーがChromeでfreee給与明細一覧(支給月タブ・該当勤務月)を開き全員「計算完了」を確認 → ②Claude in Chromeのサイドパネルを開く → ③本スキルで算出した「freee入力用(変動手当)」を、自己完結の指示文（各従業員の氏名/従業員番号＋項目別金額、基本給・みなし・皆勤は触らない、確定ボタンは本人が押す）として貼り付け → ④Chrome側Claudeが各人の明細を開き支給項目へ入力 → ⑤ユーザーが金額を照合して自身で「給与明細を確定」。
- このクラウド側ルーティンの役割は、計算して「freee入力用テーブル」と「Claude in Chromeへ貼る指示文」を生成するところまで。最終入力・確定はユーザーPC側。

## 手順
1. memory/context.md を読み、前回までのルール・人員・特記事項を把握。
2. 当月データ（上記1-4）を受領。店販内訳を店舗合計と検算（不一致なら差し戻し）。
3. freeeで前月明細を取得（固定項目・前月通勤費）。新入社/退社・雇用区分変更を確認。
4. `成果物/給与計算エンジン/calc_YYYYMM.py` と `timecard_parse_YYYYMM.py` を当月用に作成して計算。
5. 社員別の総支給と「freee入力用（変動手当）」テーブルを提示。未確定点（定期額・雇用区分相違等）は明示。
6. 成果物を `成果物/給与計算結果/YYYY-MM_スタッフ別給与.md`・`成果物/勤怠/YYYY-MM_労働時間.md` に保存し、memory を更新、commit/push。
7. freee入力は入力用テーブルを提供（必要なら皆勤等の書込可能分のみAPI反映）。

## 検算の勘所
- 店販内訳のスタッフ合計＝店舗の区分別店販合計（指名料/美容液/回数券…）に一致。
- 商品OPコミッションは (美容液+オプ)×5% が整数になることが多い（例: 8月谷本=4,576）。
- 総売上インセンティブは過去月のfreee明細と整合（谷本 851,480→42,500 等）。
